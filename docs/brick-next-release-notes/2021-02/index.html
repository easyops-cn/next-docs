2021 年 02 月

Working In Progress

注意：发布前请移除本段内容，并添加链接到 sidebars.js 中。

在 2021 年 02 月，Brick Next (2.x.x) 及 Next Builder（1.x.x）发布的新特性包括：

  • 自定义模板支持属性合并
  • 自定义模板支持属性作为变量
  • 求值表达式支持 LOCAL_STORAGE.getItem(...)
  • 新增内建处理器 localStorage.*
  • 在编排中进行权限判断
  • 在编排中进行权限预校验，支持动态权限判断

自定义模板支持属性合并​

有时候我们希望自定义模板代理的内部构件的属性可以进行数据合并，而不是整体的属性映射。例如我们定义一个自定义模板，它内部有一个表格构件，它的 columns 初始定义了一些通用列，同时希望编排者可以按需为表格增加其它的列定义。

现已支持通过 mergeProperty 等配置即可实现属性合并，例如定义一个自定义模板：

name: "tpl-extensible-table"
proxy:
  properties:
    appendColumns:
      ref: "table"
      mergeProperty: "columns"
      mergeType: "array" # "array" or "object"
      mergeMethod: "append" # "append" or "prepend" or "insertAt"
      # mergeArgs: # optional args for methods like "insertAt"
bricks:
  - brick: "presentational-bricks.brick-table"
    properties:
      # Predefined default columns
      columns:
        - dataIndex: "id"
          title: "ID"
        - dataIndex: "name"
          title: "Name"

编排时：

bricks:
  - brick: "tpl-extensible-table"
    properties:
      # User-defined extra columns
      appendColumns:
        - dataIndex: "email"
          title: "Email

更多资料详见关于 Custom Templates 的文档。

自定义模板支持属性作为变量​

有时候我们希望可以定义一些模板实例级别的变量，模板内部的构件可以在属性、事件等地方消费这些变量。注意它和 Context 上下文 的区别，后者相当于全局变量，无法将其作用域限制在某个具体的模板的实例内部。

现已支持将指定的模板属性标记为可供内部构件引用的变量，例如定义一个自定义模板：

name: "tpl-flexible-table"
proxy:
  properties:
    # 1. 将属性标记为 `asVariable: true`。
    dataIndexOfName:
      asVariable: true
bricks:
  - brick: "presentational-bricks.brick-table"
    properties:
      columns:
        # 2. 在求值占位符中使用 `TPL.*` 引用标记好的属性。
        - dataIndex: "<% TPL.dataIndexOfName ?? 'name' %>"
          title: "Name"

编排时：

bricks:
  - brick: "tpl-flexible-table"
    properties:
      dataIndexOfName: "hostname"
  - brick: "tpl-flexible-table"
    properties:
      dataIndexOfName: "username"

更多资料详见关于 Custom Templates 的文档。

求值表达式支持 LOCAL_STORAGE.getItem(...)​

支持通过 <% LOCAL_STORAGE.getItem("your-key") %> 获取 localStorage 存储的信息。

新增内建处理器 localStorage.*​

支持通过 localStorage.setItem 往 localStorage 中写入数据：

- brick: your-brick
  events:
    - action: localStorage.setItem
      args:
        - your-key
        - value

支持通过 localStorage.removeItem 从 localStorage 中移除数据：

- brick: your-brick
  events:
    - action: localStorage.removeItem
      args:
        - your-key

在编排中进行权限判断​

有时候我们需要在编排中针对用户拥有的权限来确定显示的内容、按钮的启用或禁用等，现在已支持在求值表达式中编写 <% PERMISSIONS.check("your:action-x") %> 来获取当前用户是否拥有指定的权限。

例如:

- brick: "your.any-brick"
  properties:
    disabled: "<% !PERMISSIONS.check("tool:execute") %>"

在编排中进行权限预校验，支持动态权限判断​

在路由或构件处可以定义 permissionsPreCheck 进行权限预校验，在求值表达式中支持动态权限参数。

例如:

定义 permissionsPreCheck：

routes:
  - path: "${APP.homepage}/your-page"
    permissionsPreCheck:
      - <% `cmdb:${QUERY.objectId}_instance_create` %>

校验权限：

- brick: my.button-brick
  properties:
    disabled: <% !PERMISSIONS.check(`cmdb:${QUERY.objectId}_instance_create`) %>
